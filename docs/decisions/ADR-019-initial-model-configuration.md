# ADR-019 — Initial Model Configuration

1. **Title:** Initial gateway model configuration: primary OpenAI GPT-5.1, fallback Anthropic Claude Sonnet 4
2. **Status:** Accepted
3. **Date:** 2026-07-18
4. **Owner:** Product owner
5. **Context:** ADR-004 (accepted) mandates a provider-neutral gateway with one primary and one fallback model and no dynamic routing; ADR-011 (accepted) defines the configuration-free internal contract. AOQ-01 asked which models fill the two configuration slots. These are **external product API models** — unrelated to any Claude Code / Codex session-model selection used to author these documents.
6. **Decision:** Configure the gateway with **primary model family: OpenAI GPT-5.1** and **fallback model family: Anthropic Claude Sonnet 4**. Fallback fires only for explicitly defined failure conditions or explicitly supported task categories (per ADR-011 eligibility rules). No dynamic price/quality/latency routing.
7. **Scope:** Gateway configuration values only. The provider-neutral architecture (ADR-004/011) is unchanged; this ADR selects what goes in the two slots.
8. **Explicit boundaries:** (a) **Exact API model identifiers/snapshots must be resolved and recorded before implementation** (AOQ-18) — "GPT-5.1"/"Claude Sonnet 4" are family selections, not pins. (b) Provider-specific model names never appear in product-domain modules — configuration and adapters only. (c) Model configuration is replaceable without business-logic changes (ADR-011 contract guarantees this). (d) Prompts and structured-output schemas are tested against **both** models. (e) **No silent fallback** where switching could materially change output quality, cost, policy posture, or data processing — material-decision task classes either queue or surface the degradation honestly (extends ADR-011 eligibility with a user-visibility rule). (f) Every call records provider, model identifier, model version/snapshot where available, latency, usage, estimated cost, **fallback reason**, and correlation ID (extends ADR-011's recording set with fallback reason). (g) Credentials server-side only (ADR-003/021). (h) No secrets or unrelated tenant data in model context (invariant 12; context assembly rules, AI-AND-WORKER §1).
9. **Alternatives considered:** Anthropic-primary/OpenAI-fallback (viable; owner selected the reverse); single-provider dual-model (fails NFR-019's failure-domain separation); deferring selection further (blocks the evaluation suite and Phase 2 build).
10. **Positive consequences:** Two independent failure domains; evaluation suite can start; schema/prompt portability enforced from the first template.
11. **Negative consequences:** Dual-model test matrix from day one; two provider accounts/agreements to manage.
12. **Security implications:** Two providers in the data path — both must appear in the subprocessor register with processing locations documented (ADR-005); data-path disclosure copy must name both (ADR-003 §16).
13. **Operational implications:** **Pre-production evaluation gate is mandatory**, covering: adaptive follow-up questions; fact and assumption extraction; contradiction detection; three-option strategy generation; research synthesis; citation preservation; structured-output validity; refusal and safety behavior; revision consistency; cost and latency. The gate **chooses configuration values** (which model serves which task class, fallback eligibility, thresholds — AOQ-19) — it does not rewrite the provider-neutral architecture. Fallback-rate and eval-regression monitoring per ADR-017.
14. **Portability implications:** Swapping either slot is configuration + regression suite (ADR-011 §13); no product-code changes.
15. **Reversal cost:** Low (that is the point of the gateway).
16. **Requirement IDs:** NFR-019, NFR-015, NFR-009, NFR-018, USAGE-001, TOOL-002, DISC-001, STRAT-001, WORK-002, WORK-003, WORK-004, NFR-021.
17. **Governing architecture ADRs:** ADR-004 (accepted strategy), ADR-011 (gateway contract), ADR-003 (key ownership), ADR-005 (residency documentation).
18. **Follow-up work:** AOQ-18 pin exact model identifiers/snapshots; AOQ-19 define evaluation thresholds; build the evaluation suite before Phase 2 AI features enter production paths; subprocessor register entries for both providers.
19. **Review triggers:** Model deprecation notice from either provider; material cost change (>25% per ADR-003 trigger); evaluation regression below thresholds; new privacy or residency requirement affecting either provider; repeated fallback failure; a stronger model achieving a defined evaluation threshold at comparable cost.
