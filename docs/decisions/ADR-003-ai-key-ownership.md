# ADR-003 — AI Key Ownership

1. **Title:** Platform-managed AI-provider access vs BYOK
2. **Status:** Accepted
3. **Date:** 2026-07-18
4. **Decision owner:** Product owner
5. **Context:** Every worker, the interview engine, and strategy generation depend on model calls. Who owns the provider relationship determines metering, cost exposure, privacy posture, and credential architecture — all MVP-critical path. Three models were analyzed in OWNER-DECISION-PACK.md (Decision 3) against 12 criteria.
6. **Decision:** **Platform-managed model-provider access for MVP.** Customers are not required to provide AI API keys during initial onboarding. Before beta, the platform-managed model system must include: per-company usage recording; per-account usage recording; model and model-version tracking; token (or equivalent) usage measurement; estimated provider cost; hard usage limits; rate limits; budget alerts; abuse detection; provider timeout handling; provider failure normalization; secret isolation; server-side credential use; no provider keys exposed to browsers or clients; redacted logging; and clear disclosure of the AI-provider data path. **Optional BYOK is post-MVP** and must not enter the first implementation unless a later approved decision changes scope.
7. **Alternatives considered:** BYOK-only (strongest privacy story, fatal onboarding friction for the ADR-001 segment, output-quality variance, key-support burden); hybrid at launch (correct end-state, but building both paths in MVP doubles credential/metering/support surface for users who don't yet exist). Full tables preserved in the decision pack.
8. **Reasons:** Only platform-managed access preserves frictionless onboarding for non-technical founders and the output-quality consistency the worker acceptance criteria assume; every platform-key risk has a named control in the required list above.
9. **Positive consequences:** Zero-key onboarding; uniform model quality and safety configuration; single metering and limit point; simplest credential surface (few platform keys, NFR-018).
10. **Negative consequences:** AI cost sits on platform margin; abuse hits the platform bill; provider price changes reprice unit economics.
11. **Risks:** Margin erosion; free-tier/runaway abuse; privacy perception (customer business content transits the platform's provider account); provider outage becomes a platform incident.
12. **Mitigations:** The 16-control list above is a **beta launch condition**, not aspiration — mapped to USAGE-001 (usage recording), POL-001/NFR-015 (limits and hard caps), TOOL-002 (call audit metadata), TASK-004/USAGE-002 (cost estimation), NFR-010 (rate limiting/abuse baseline), NFR-019 (provider failure handling), NFR-018 (secret isolation, server-side use, no keys to clients), NFR-009 (redacted logging). Data-path disclosure is a new obligation (see follow-ups). BYOK later restores the stronger privacy posture for those who want it.
13. **Reversal cost:** **Medium** — adding BYOK later is contained because ADR-004's gateway abstracts key origin; removing platform keys entirely would be a pricing-model rupture (unlikely, costly).
14. **PRD requirement IDs affected:** USAGE-001, USAGE-002, POL-001, NFR-009, NFR-010, NFR-015, NFR-018, NFR-019, TOOL-002, TASK-004, BILL-002, INTEG-002.
15. **Architecture areas affected:** Model gateway (ADR-004) as the single metering/limit point; platform secret vault; abuse-detection and signup-friction design; billing-reconciliation pipeline.
16. **Follow-up decisions:** Two owner-visible refinements flagged rather than silently absorbed: (a) **per-account usage rollup** — USAGE-001's acceptance criteria specify company/task attribution; the approved decision adds account-level recording, which requires a small PRD amendment extending USAGE-001 (no new architecture); (b) **AI data-path disclosure copy** — required before beta; lands with NFR-011/terms work in Phase 7. Also: initial usage-cap values (before beta); BYOK roadmap timing (future decision).
17. **Review trigger:** Alpha unit economics failing the D-02 model; an enterprise design partner requiring BYOK; a provider pricing change >25%.
